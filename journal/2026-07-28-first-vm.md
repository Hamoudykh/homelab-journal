# 2026-07-28 — First VM: infra01

**Goal:** create the first guest on `pve01` — a Debian VM that will become the lab's DNS
and DHCP server.

## What was built

**infra01** — VM 100 on `pve01`

| | |
|---|---|
| OS | Debian 13 (trixie), no desktop, SSH server |
| Resources | 2 vCPU, 2 GB RAM, 16 GB disk on `local-lvm` |
| Network | bridge `vmbr0`, VirtIO, interface `ens18`, `192.168.1.174` (DHCP) |
| Guest agent | `qemu-guest-agent` running |
| Autostart | enabled — comes up with the host |

ISO fetched to `/var/lib/vz/template/iso` on the host. Downloaded at 91 MB/s, which was
also the first proof the gigabit fix from earlier had actually taken.

## Proxmox storage

Two pools exist by default, and they hold different things:

- **`local`** — a directory. Holds ISOs, container templates, backups.
- **`local-lvm`** — LVM-thin. Holds VM disk images.

The ISO goes in `local`; the VM's virtual disk goes in `local-lvm`.

## Repository fix

The host's `apt update` had been failing. Proxmox ships with the **enterprise** repository
enabled, which requires a paid subscription and returns an error without one.

Fixed via **pve01 → Updates → Repositories**:

- Disabled `enterprise.proxmox.com/debian/pve` (pve-enterprise)
- Disabled `enterprise.proxmox.com/debian/ceph-squid` (Ceph enterprise, unused)
- Kept both `debian.org` repos — those are Debian's own and are required
- Added the **no-subscription** repo (`download.proxmox.com/debian/pve`)

Then refreshed and ran the upgrade. A kernel update landed, so the node was rebooted onto
`7.0.14-6-pve`.

The "no-subscription repository is not recommended for production" warning is expected and
harmless in a lab.

## Reboot test

Rebooting after the kernel update doubled as the first real test that the whole stack
recovers unattended. Verified from a separate machine:

```
pve01 Proxmox    192.168.1.6:8006     -> UP
pve01 SSH        192.168.1.6:22       -> UP
pve01 AMT        192.168.1.6:16992    -> UP
infra01 SSH      192.168.1.174:22     -> UP
```

The VM came back on its own because autostart was enabled before the reboot.

## Notes

- **Two machines now, not one.** `192.168.1.6` is the physical host; `192.168.1.174` is a
  guest inside it. Independent IPs, independent SSH, independent everything. Reaching the VM
  no longer requires going through the Proxmox console.
- Debian blocks **root SSH login with a password** by default, so day-to-day access is via
  the normal user account, then `su -`.
- The installer's timer defaults to **speech synthesis** if no key is pressed within 20
  seconds — which then hangs looping on "no sound card detected" in a VM. Reset and press
  Enter promptly.
- A snapshot named `fresh` was intended before first boot as a rollback point.
