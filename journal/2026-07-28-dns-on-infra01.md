# 2026-07-28 — DNS for lab.home.arpa on infra01

**Goal:** stop referring to machines by IP address. Run a real DNS server for the lab domain.

**Outcome:** dnsmasq on `infra01` resolves `lab.home.arpa` names and forwards everything
else upstream. `pve01` now uses it.

## Why dnsmasq

It does DNS forwarding, local records, DHCP, and TFTP/PXE in one small daemon. DNS is the
immediate need, but DHCP and PXE are both on the roadmap — using one tool for all three
avoids replacing it later.

## Config

`/etc/dnsmasq.d/lab.conf`:

```
domain=lab.home.arpa
local=/lab.home.arpa/
expand-hosts

no-resolv
server=1.1.1.1
server=9.9.9.9

interface=ens18
listen-address=127.0.0.1,192.168.1.174
bind-interfaces

host-record=pve01.lab.home.arpa,pve01,192.168.1.6
host-record=pve01-amt.lab.home.arpa,pve01-amt,192.168.1.6
host-record=infra01.lab.home.arpa,infra01,192.168.1.174
```

**Upstream resolvers are public (`1.1.1.1`, `9.9.9.9`), deliberately not the router.** If the
router is later configured to use infra01 for DNS, and infra01 forwards back to the router,
that is a resolution loop. Forwarding straight to public resolvers avoids it.

`local=/lab.home.arpa/` means dnsmasq answers for that domain authoritatively and never
forwards those queries upstream — the outside world has no idea what `pve01` is, so asking
would only waste time and leak internal names.

## The /etc/hosts gotcha

First test result:

```
pve01.lab.home.arpa     -> 192.168.1.6      OK
pve01-amt.lab.home.arpa -> 192.168.1.6      OK
infra01.lab.home.arpa   -> 127.0.1.1        WRONG
debian.org              -> 151.101.2.132    OK
```

dnsmasq reads `/etc/hosts` (visible in its startup log: `read /etc/hosts - 15 names`), and
Debian's installer writes a `127.0.1.1 infra01.lab.home.arpa infra01` line there. That
entry took precedence over the `host-record` in the config.

Fixed by pointing the hosts entry at the real address:

```bash
sed -i 's/^127\.0\.1\.1.*/192.168.1.174\tinfra01.lab.home.arpa infra01/' /etc/hosts
systemctl restart dnsmasq
```

Retest — all four correct.

## Rollout

`pve01` → System → DNS → first server set to `192.168.1.174`. Verified from the host:

```bash
ping -c2 infra01.lab.home.arpa   # lab name
ping -c2 debian.org              # forwarded upstream
```

Both work.

**Deliberately did not change the router's DNS yet.** Doing so points every device in the
house at infra01, which means a VM being down takes the whole household's name resolution
with it. Change one consumer first, confirm it works, then widen the blast radius.
